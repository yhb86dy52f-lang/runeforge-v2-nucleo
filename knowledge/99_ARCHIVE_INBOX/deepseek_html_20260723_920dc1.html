Informe Técnico de Integración de Telemetría

Proyecto: Puente de datos entre sensor Escort TD-BLE y rastreador CalAmp LMU-2630MB.

Estado: Documentación verificada y validada. Pendiente de extracción de UUIDs mediante nRF Connect.

✅ Verificación de hardware confirmada: El rastreador CalAmp LMU-2630MB tiene capacidad BLE nativa y el sensor Escort TD-BLE emite paquetes en modo Advertising (sin necesidad de emparejamiento GATT complejo), lo cual es la base para una integración robusta y de bajo consumo.
⚠️ ADVERTENCIA CRÍTICA DE FIRMWARE: El sensor de tu flota (SN: 260463959191, MAC: D1:6D:2A:5B:BE:07) pertenece a la carcasa de diseño anterior (anterior al SN 268489).
NO UTILICES EL FIRMWARE 1.4.0 en este sensor, ya que está diseñado exclusivamente para las nuevas carcasas. La versión estable y segura para tu sensor es la 1.3.9.

1. Resumen Ejecutivo de la Arquitectura

Se ha descartado el uso de soluciones externas basadas en ESP32 para el entorno vehicular, debido a los altos riesgos de interferencia electromagnética con el GPS y la falta de certificación automotriz.

Arquitectura Final Elegida:

  • Sensor: Escort TD-BLE (BLE 4.0, Modo Advertising).
  • Puente: Sin hardware extra. El LMU-2630MB lee directamente los paquetes BLE.
  • Procesamiento: El rastreador lee el valor ADC (1-4095) y lo envía al servidor.
  • Calibración: El servidor o el sensor (aplicando la tabla de 28 puntos) convierten el ADC a litros reales.

Flujo de trabajo recomendado

  1. Extraer las UUIDs exactas de publicidad usando la aplicación nRF Connect en un teléfono Android (paso obligatorio).
  2. En el DMC de CalAmp, configurar la opción "BLE Custom" con la MAC y UUIDs descubiertas.
  3. Configurar el puerto IO: Fuel Level para que reciba el dato del offset de bytes correspondiente.
  4. Si se prefiere que el sensor envíe litros directamente, cargar el archivo CSV en la app Escort Configurator (función "Convertir en litros").

3. Configuración del DMC de CalAmp (Integración BLE Nativa)

CRÍTICO: El usuario debe descargar la aplicación nRF Connect en su teléfono, conectarse al sensor (MAC D1:6D:2A:5B:BE:07) y anotar el Service UUID y Characteristic UUID de la pestaña GATT. El documento "Firmware description" no contiene estas UUIDs.

Pasos a seguir en el DMC Configurator de CalAmp:

  1. Conexión: Conectar el LMU-2630MB al PC vía USB y abrir el DMC Configurator.
  2. Menú Bluetooth: Navegar a la pestaña de Bluetooth 4.0 o BLE Settings.
  3. Modo Custom BLE: Habilitar la casilla "Enable" para el BLE Custom.
  4. Ingresar datos del sensor:
    • MAC Address: D1:6D:2A:5B:BE:07
    • Service UUID (Obtenido de nRF): [PEGAR_UUID_DEL_SERVICIO_AQUÍ]
    • Characteristic UUID (Obtenido de nRF): [PEGAR_UUID_DE_LA_CARACTERÍSTICA_AQUÍ]
    • Data Offset (Interpretación de bytes): Buscar en la documentación faltante o usar nRF Connect para verificar qué bytes corresponden al ADC. (Normalmente Bytes 0 y 1 o 2 y 3).
  5. Mapeo de datos: Asignar el valor extraído a la E/S IO: Fuel Level.
  6. Guardar: Presionar "Save to Device" y esperar el reinicio.

4. Comandos SMS de Configuración Remota y Herramientas

Método de configuración remota vía SMS (Flota)

Una vez que se haya creado un archivo de configuración (.cfg) con los parámetros del paso anterior, se puede desplegar a la flota utilizando el comando SMS de CalAmp.

[Tu_Contraseña_de_Configuración],cfgload

Ejemplo práctico: Si la contraseña es 1234, el SMS debe ser 1234,cfgload. El rastreador descargará la configuración desde la nube y aplicará los parámetros del sensor automáticamente.

Código PowerShell para la gestión de datos (Generación JSON/CSV)

El siguiente script PowerShell permite generar automáticamente el archivo calibration_data.json y calibration_data.csv a partir de los datos depurados del usuario. Puede ser utilizado para subir la tabla a plataformas de monitoreo o para verificar la integridad de los 28 puntos.

# Script de PowerShell para generar los archivos de calibración validados del usuario.
# Este script está diseñado para ser ejecutado en sistemas Windows o PowerShell Core.

$CalibrationData = @"
1,1
153,8
305,20
458,34
611,50
763,68
916,88
1069,109
1221,130
1374,152
1527,175
1679,199
1832,222
1985,246
2137,270
2290,294
2443,318
2595,341
2748,364
2901,386
3053,407
3206,427
3359,447
3511,464
3664,480
3817,494
3969,505
4095,511
"@.Trim() -split "`r`n" | ForEach-Object { $_.Trim() } | Where-Object { $_ -ne "" }

if ($CalibrationData.Count -ne 28) {
    Write-Warning "Se esperaban 28 filas de calibración, pero se encontraron $($CalibrationData.Count)."
}

$JSONOutput = @{
    sensor_model = "ESCORT TD-BLE"
    serial_number = "260463959191"
    mac_address = "D1:6D:2A:5B:BE:07"
    firmware_compatible_version = "1.3.9"
    calibration_points = @()
}

foreach ($line in $CalibrationData) {
    $parts = $line -split ","
    $JSONOutput.calibration_points += @{adc = [int]$parts[0]; volume = [int]$parts[1]}
}

$JSONOutput | ConvertTo-Json -Depth 3 | Out-File -FilePath "calibration_data_verified.json" -Encoding utf8

$CSVHeader = "ADC_Raw,Volumen"
$CSVOutput = @($CSVHeader) + $CalibrationData
$CSVOutput | Out-File -FilePath "calibration_data_verified.csv" -Encoding utf8

Write-Host "Archivos generados exitosamente:" -ForegroundColor Green
Write-Host "  - calibration_data_verified.json" -ForegroundColor Cyan
Write-Host "  - calibration_data_verified.csv" -ForegroundColor Cyan
Write-Host "Se ha omitido la fila final (0,0) por ser un artefacto del archivo CSV original." -ForegroundColor Yellow
