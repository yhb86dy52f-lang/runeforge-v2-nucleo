Consola de Despliegue: Escort TD-BLE & CalAmp LMU-2630MB

Documentación técnica optimizada para integración directa sin hardware de puente

1. Especificaciones Técnicas Aclaradas

Para garantizar la interoperabilidad sin hardware externo como el ESP32[cite: 23], el sistema depende de variables estrictas:

  • Identidad del Sensor: Modelo ESCORT TD-BLE [cite: 2], MAC Address D1:6D:2A:5B:BE:07 [cite: 2, 5], Número de Serie 260463959191[cite: 2, 15].
  • Regla Crítica de Firmware: El firmware máximo compatible para este hardware específico es la versión 1.3.9[cite: 2, 15]. El flasheo a la versión 1.4.0 provocará un bloqueo irreversible del dispositivo[cite: 24].
  • Transmisión de Datos (Sensor): Opera bajo BLE Advertising (modo broadcast) enviando paquetes con un intervalo de 3000 ms[cite: 2].
  • Adquisición de Datos (Rastreador): El CalAmp lee el valor ADC puro, que oscila en un rango válido de 1 a 4095[cite: 7].
  • Calibración Matemática: La conversión de ADC a volumen requiere la aplicación exacta de una tabla validada de 28 puntos de calibración (sin ceros residuales)[cite: 3, 13, 25].

2. Optimización de la Arquitectura y Scripts

La integración BLE nativa y directa [cite: 23] reduce puntos de falla. Las optimizaciones aplicadas son:

Optimización del Script PEG (CalAmp): El script actual busca la MAC del sensor al registrarse un evento BLE (on BLE_Event) [cite: 6] y extrae el valor ADC basándose en BYTE_OFFSET 2 y BYTE_SIZE 2[cite: 5].
  • Problema actual: Utilizar Send_Record_Now() [cite: 8] en cada evento de publicidad saturará la red celular.
  • Solución Optimizada: El script solo debe actualizar el acumulador local mediante Set_Fuel_Level_1(raw_adc)[cite: 7]. Si hay un error, lo asigna a 0[cite: 9]. El envío de datos debe delegarse al motor de reportes estándar de CalAmp.
Optimización del Procesamiento (PowerShell): El script de validación está diseñado para Windows o PowerShell Core [cite: 11] y genera eficientemente los archivos JSON y CSV en formato UTF-8 (-Encoding utf8) [cite: 16, 17], excluyendo la fila inútil (0,0)[cite: 18].
  • Recomendación de Escalabilidad: Para flotas grandes, envuelve esta lógica en un bloque param() para procesar múltiples vehículos dinámicamente.

3. Recursos Necesarios para Terreno

  • Dispositivo Móvil Android/iOS: Con Bluetooth 4.0/5.0 habilitado[cite: 50].
  • Software de Diagnóstico: La aplicación nRF Connect es de uso obligatorio[cite: 28].
  • Parámetros a Descubrir: El técnico debe usar nRF Connect para obtener el Service UUID, el Characteristic UUID y confirmar el Byte Offset real[cite: 28]. Esto ajustará los parámetros #define BYTE_OFFSET en el script PEG final[cite: 4, 5].
  • Configuración: CalAmp DMC Configurator para cargar el entorno BLE Custom o el Script PEG[cite: 26].
  • Calibración: Los archivos calibration_data_verified.csv y .json generados para importación[cite: 17, 18, 25].
